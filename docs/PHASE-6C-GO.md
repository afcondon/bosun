# Phase 6C (Go column) — the Go binary does the devops

**Done & reproducible.** A PureScript program compiled by **backend-go** to a
native Go binary runs the pure pipeline (`reconcile → validate → plan →
applyScript`) *as Go* and then **executes** the deploy via os-exec. Verified:
it launches two HTTP servers → `HTTP 200`.

## Run it

```bash
cd /path/to/bosun
./scripts/go-apply.sh
```

No manual setup. The script builds Bosun, transpiles the I/O-free harness
`Bosun.Conformance.ApplyMain` via backend-go, copies in `runtime.go` **and
Bosun's own foreign**, `go build`s, runs the binary, and `curl`s the two ports.
Expected tail:

```
apply (Go column): 2 command(s)
  OK  cd /tmp/bosun-hello-go && nohup python3 -m http.server 8774 …&
  OK  cd /tmp/bosun-hello-go && nohup python3 -m http.server 8773 …&
apply (Go column): done.
   8773 -> HTTP 200
   8774 -> HTTP 200
```

Clean up with `pkill -f 'http.server 877'`.

## Why there's no backend-go edit (the layering fix)

The one piece of hand-written Go that Bosun needs — the os-exec shim — is an
**app-specific foreign**, so it lives in the **Bosun repo**, not in backend-go:

```
conformance/go/bosun_apply_foreign.go    # package main; Bosun_Conformance_ApplyMain_execLineImpl
```

backend-go has no per-module foreign-file mechanism, but `go build *.go` over
the output dir resolves any `package main` symbol — so `go-apply.sh` just copies
this file in next to the generated sources. Result:

- **backend-go stays app-agnostic** — no Bosun shim in its shared `runtime.go`.
- **the foreign is version-controlled with Bosun** and can't be clobbered by
  anything in backend-go.

> Earlier this foreign was added to `backend-go/runtime.go` directly; that was
> reverted in favour of this. (`runtime.go`'s `// Generated by psgo … Do not
> edit` header is a stale carry-over from the Phase-1 `prelude.go` model — the
> Phase-2 `runtime.go` is in fact hand-maintained and copied directly by every
> build script, so editing it was safe, just badly-layered. The header is worth
> correcting in backend-go someday, but that's a backend-go concern.)

## The os-exec foreign (reference)

`conformance/go/bosun_apply_foreign.go` implements
`execLineImpl :: EffectFn1 String { ok :: Boolean, code :: Int, message :: String }`.

backend-go foreign ABI (read off the runtime catalogue):
- a foreign import `Module.Path.name` → a global `var Module_Path_name any`;
- an `EffectFnN` is an uncurried `func(args ...any) any` performed synchronously;
- a PureScript record is a `map[string]any` keyed by label;
- `Int`→`int`, `String`→`string`, `Boolean`→`bool`.

**Gotcha:** a backgrounded launch (`… &`) must be `Start()` without `Wait` and
with nil stdio — `CombinedOutput` on a `… &` line **hangs**, because the
daemonising child keeps the output pipe open. (This bit us once; the node `.js`
twin already guarded it.) Synchronous commands (docker, ssh) use
`CombinedOutput` with captured output and a real exit code.
